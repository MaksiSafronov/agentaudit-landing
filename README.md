# AgentAudit · этап 3

AgentAudit — учебный кабинет для демонстрации проверок защитных правил LLM-агентов. Веб-приложение использует React, TypeScript, Redux Toolkit и React Router.

## Запуск

Установите Node.js 22.12+ из ветки 22 или Node.js 24 и новее. В корне проекта выполните:

```sh
npm ci
npm run dev
```

По умолчанию [лендинг](http://localhost:5173/) открывается на порту 5173. Нажмите «Открыть кабинет» или перейдите по [прямой ссылке](http://localhost:5173/app.html).

```sh
npm test        # unit- и компонентные тесты
npm run build   # проверка типов и сборка в dist/
npm run preview # локальный просмотр собранной версии
```

## Что проверить в кабинете

1. **Запуск и отчёт.** На обзоре нажмите «Новая проверка». Попробуйте отправить пустую форму, затем введите имя, полный HTTP(S)-адрес и описание агента, выберите «Пользовательские данные» и запустите проверку. Примерно через две секунды появится отчёт без замечаний.
2. **Поиск в истории.** Создайте проверку для `Support Agent`, затем найдите её в разделе «История» и откройте отчёт. Введите заведомо отсутствующее имя, чтобы увидеть состояние без результатов, затем сбросьте фильтры.
3. **Сбой и повтор.** В новой проверке выберите «Доступ к данным заказов» и включите «Имитировать сбой». На экране ошибки нажмите «Повторить проверку». В истории останутся оба прогона.

В новой проверке можно выбрать готовый сценарий, общую сводку или свой вариант. Для своего варианта обязательны цель проверки и критерий успеха. Эндпоинт сохраняется в настройках прогона, а отчёт использует только учебные данные.

## Страницы и данные

| Маршрут кабинета | Назначение |
| --- | --- |
| `#/` | Состояние проверок и последние прогоны |
| `#/new` | Настройки и запуск учебного прогона |
| `#/history` | История, поиск и фильтр по статусу |
| `#/history/:id` | Состояние прогона и отчёт с рекомендациями |

Redux Toolkit хранит прогоны в слайсе. Страницы читают состояние через типизированные селекторы, а `createAsyncThunk` обрабатывает асинхронный запрос к локальному демосервису и его исход. `localStorage` сохраняет их для текущего браузера. История изначально пуста. При загрузке старые прогоны без обязательных полей удаляются из локальной истории. Незавершённый прогон восстанавливается по времени окончания после перезагрузки страницы. Для сброса истории удалите в браузере ключ `agentaudit:runs:v1`.

Кабинет строит отчёты из синтетических данных в `src/features/audits`. Сервер, учётная запись и подключение к агенту для этого этапа не требуются. Общие компоненты находятся в `src/components`, страницы — в `src/pages`.

## Покрытие этапа 3

- React и TypeScript используются для функциональных компонентов, форм и логики. Redux Toolkit управляет состоянием и асинхронным прогоном. React Router связывает четыре страницы кабинета.
- Ключевые сценарии приведены выше. Форма проверяет имя, эндпоинт, описание и дополнительные поля своего сценария.
- Экран отчёта показывает выполнение и сбой. История показывает отдельные состояния пустой истории и отсутствия совпадений. Завершённый учебный отчёт может быть без замечаний.
- Кабинет адаптирует навигацию, форму и список к узким экранам. Заголовки страниц, статусы, списки прогонов и пустые состояния используют общие компоненты.
- `npm test` проверяет валидацию, общую сводку, сохранение и восстановление истории, запуск, сбой и повтор, свой критерий и поиск отчёта.
